How it works

  1. Pick an order. The contract builds the request it expects from the order's supplier and trusts one signer per registry.
  2. Load a signed record of that supplier (the Airnode's signed response, as JSON: {"source":"ch","supplierId":"09729896","requestHash":"0x…","timestamp":"…","data":"0x…","signature":"0x…"}): a sample (old on purpose), your own file from fetch-evidence.sh, or Fresh local record on the local chain. It must be at most 300 s old, or every attack stops at the freshness check.
  3. Run the full tamper test. Each attempt is the contract's own verdict: an eth_call of submitEvidence from 0x…dEaD, so nothing changes on chain. It passes when the valid record is accepted and every attack is rejected.
  4. Replay last. Send the valid record for real, then replay it: the contract answers Replayed.

Amber tile, or "Not tested": the record could not test that attack, because it is too old, already sent, or for another order, so an earlier check stopped it. What to do: load a fresh record (Fresh local record on the local chain, fetch-evidence.sh elsewhere, see the Judge kit) and run again. Attack a fresh record before you send it for real; afterwards (a) and (d) stop at NotNewer or Replayed.

Glossary: the contract's errors and the words on this page
Contract errors
WrongSignerThe signature recovers to another key than the Airnode the contract trusts: the signed bytes were edited, or another key signed.
WrongRequestThe record answers another request (company, operation or projection) than the one the order expects.
StaleResponseSigned more than the maximum age (300 s) before the chain's time.
FutureResponseDated more than 60 s after the chain's time.
ReplayedThis exact signed record was already used once.
NotNewerThe order already accepted a record signed at the same time or later.
NotActiveThe order is held or closed, so it accepts no new evidence.
SupplierFailedA clean record older than a known register failure of this supplier.
Words on this page
Airnode (the signer)The API3 node that signs each register answer. The contract trusts one Airnode address per registry and acts only on records whose signature recovers to it. On the local chain a public anvil test key plays this part.
Request hashA hash (keccak256) of the exact question asked: operation, company and the fields wanted. The contract builds the one it expects from the order's registry and supplier, so a record that answers another question fails with WrongRequest.
DigestThe fingerprint of one signed record: keccak256 of its request hash, time and data. The Airnode signs it, and the contract stores each digest it accepts, so the same record cannot count twice (Replayed).
Max ageHow old a record may be, measured against the chain's clock: 300 s on this contract. An older record fails with StaleResponse.
Payment permitThe contract's go-ahead to pay the order's next milestone to the supplier. A genuine, fresh record that passes every check and every rule issues it; it expires, and then a fresh record is needed.
SimulatedEach attempt is a simulation (an eth_call): the node runs submitEvidence as if 0x…dEaD had sent it and returns the contract's answer. No transaction, no wallet, no gas; nothing changes on chain.
x402Pay per request over HTTP: AirnodeHub answers "402 Payment Required" until the $0.01 is paid (aUSD on Base Sepolia), then returns the signed record.
